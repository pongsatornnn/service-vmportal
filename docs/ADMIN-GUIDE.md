# คู่มือผู้ดูแล Portal

คู่มือแบบอ่านทีละหัวข้ออยู่ในเว็บที่ **คู่มือผู้ดูแลระบบ** มีค้นหาและปุ่มคัดลอกคำสั่ง ใช้ค่า Node/Pool/Storage/Bridge/Template ปัจจุบันจาก Setup ไม่มีการรันคำสั่งให้โดยอัตโนมัติ

## ลำดับเริ่มต้น

1. เตรียม Pool, Storage, Bridge และ Service User/Token บน Proxmox
2. เตรียม Golden Template: Cloud-Init + SSH policy + QEMU Guest Agent
3. Portal → ตั้งค่า → Proxmox: Endpoint/Token/CA → เลือกทรัพยากร → บันทึกและตรวจสอบ → เปิดใช้งาน
4. อนุมัติบัญชีและคำขอใน **รออนุมัติ** ตรวจงานที่ **กิจกรรม** แล้วทดสอบ VM แรกหลัง Admin อนุญาต

## ระดับผู้ดูแลใน Portal

ทุกระดับใช้ VM ของตัวเองได้เหมือนผู้ใช้ทั่วไป

การจัดการบัญชี (ปรับทรัพยากร, โค้ดกู้คืน, เปลี่ยนสิทธิ์, ลบบัญชี) ทำได้เฉพาะกับบัญชีที่ระดับต่ำกว่าตนเอง เรียงเป็น ผู้ใช้ < Admin < ผู้ดูแลหลัก < ผู้ดูแลสูงสุด ระดับเดียวกันหรือบัญชีของตนเองทำไม่ได้

บัญชีในเครื่อง VM (username ที่ตั้งตอนขอสร้าง) แสดงให้เจ้าของ VM เห็นเท่านั้น ผู้ดูแลทุกระดับรวมถึงผู้ดูแลสูงสุดดูไม่ได้ แม้จะจัดการ VM นั้นได้

| ระดับ | ทำได้ |
| --- | --- |
| Admin | ดู VM และสถานะของทุกคน, อัปเดต IP / ตรวจสถานะ, อนุมัติหรือปฏิเสธบัญชี คำขอสร้าง VM และคำขอรีเซ็ตรหัส VM, ปรับทรัพยากรและออกโค้ดกู้คืนเฉพาะผู้ใช้ทั่วไป, ทำต่อหรือปิดงานค้าง |
| ผู้ดูแลหลัก | ทุกอย่างของ Admin และ: ตั้งค่า Proxmox / Template / Session, เปิด-ปิด Restart และ Console ของ VM ทุกคน, อนุมัติลบ VM, ปรับทรัพยากรและออกโค้ดกู้คืนให้ Admin, ยกระดับ/ลดสิทธิ์ Admin และลบบัญชีผู้ใช้หรือ Admin |
| ผู้ดูแลสูงสุด | ทุกอย่างของผู้ดูแลหลัก และมอบหรือถอนสิทธิ์ผู้ดูแลหลัก, ปรับทรัพยากร ออกโค้ดกู้คืน และลบบัญชีของผู้ดูแลหลัก (Admin คนแรกที่สร้างตอนติดตั้ง มีคนเดียว) |

มอบสิทธิ์ที่หน้า **ผู้ใช้** → **จัดการ** → **มอบสิทธิ์ผู้ดูแลหลัก** (บัญชีต้องเป็น Admin ก่อน) ต้องพิมพ์ชื่อผู้ใช้และรหัส Portal ของตนเพื่อยืนยัน ผู้ดูแลหลักเปลี่ยนสิทธิ์ของผู้ดูแลหลักคนอื่นไม่ได้ โค้ดกู้คืนของผู้ดูแลหลักออกได้เฉพาะผู้ดูแลสูงสุด ส่วนผู้ดูแลสูงสุดลืมรหัสให้รีเซ็ตจาก Server ([รหัสผ่านและการกู้คืน](PASSWORD-RECOVERY.md))

คู่มือสำหรับผู้ใช้ทั่วไปอยู่ในเว็บที่เมนู **คู่มือการใช้งาน** และใน [USER-GUIDE.md](USER-GUIDE.md)

## สิทธิ์ Proxmox

สร้าง Custom Roles ใน Datacenter → Permissions → Roles แล้ว Add User Permission และ API Token Permission ทั้งคู่ เปิด Propagate ที่ Pool เมื่อใช้ Privilege Separation สิทธิ์ต้องมีในทั้ง User และ Token ไม่ให้ Administrator

| Path ตัวอย่าง | สิทธิ์ |
| --- | --- |
| /vms/9200 (Template ปัจจุบัน) | VM.Clone, VM.Audit |
| /pool/Portal-Service | VM.Allocate, VM.Audit, VM.PowerMgmt, VM.Config.CPU/Memory/Disk/Network/Cloudinit/Options |
| /storage/local-lvm | Datastore.AllocateSpace |
| /nodes/Node3 | Sys.Audit |
| /sdn/zones/localnetwork/VLAN48 | SDN.Use; ตรวจ Path จริงของ Bridge บนระบบ |
| /pool/Portal-Service | VM.Console, VM.GuestAgent.Audit |
| /pool/Portal-Service หรือเฉพาะ /vms/VMID | VM.GuestAgent.Unrestricted เมื่ออนุญาตรีเซ็ตรหัส Guest; เป็นสิทธิ์กว้างภายใน Guest ให้ Admin พิจารณาขอบเขต |

Service User ตัวอย่าง vmportal@pve, Token vmportal@pve!portal-api ต้องใช้ชื่อจริงตาม Setup เมื่อเปลี่ยน Template ให้เพิ่ม Clone/Audit บน VMID ใหม่ด้วย

## Golden Template

คู่มือบนเว็บรวมการสร้าง Golden Template ไว้หัวข้อเดียว ใช้แนวทาง Ubuntu 24.04 Cloud Image → ติดตั้งเครื่องมือ → SSH policy → QEMU Guest Agent → Clean → Convert ให้เป็นแบบ Template ที่ใช้งานอยู่ VMID 9200 (`ubuntu2404-template-portal`) รายละเอียดตาม [คู่มือ Golden Template](TEMPLATE-SSH-PASSWORD.md) ไม่มีทางเลือก Clone Template เก่าซ้อนอีกชุด ตัวอย่างเตรียมเครื่องใช้ 9300 ต้องตรวจว่าเลขว่างก่อน และไม่แก้ Template 9200 โดยตรง

เปิด QEMU Guest Agent ใน Proxmox Options ก่อน Start มี scsi0/Cloud-Init drive/net0 ต่อ VLAN48 ตั้ง user ubuntu และรหัสชั่วคราวผ่าน Cloud-Init UI

ภายใน Ubuntu Guest:

```bash
sudo cloud-init status --wait
sudo apt update
sudo apt install -y nano net-tools curl wget htop unzip zip jq dnsutils iputils-ping ca-certificates openssh-server cloud-init qemu-guest-agent
sudo systemctl start qemu-guest-agent
sudo systemctl status qemu-guest-agent --no-pager
```

ตั้ง Cloud-Init ssh_pwauth: true, disable_root: true, ssh_deletekeys: true และ SSH PasswordAuthentication yes / PubkeyAuthentication yes / PermitRootLogin no ตาม [คู่มือ Template](TEMPLATE-SSH-PASSWORD.md) ตรวจ sshd -t และ sshd -T แล้วทดสอบ SSH ก่อน clean

หาก Agent dependency failed และไม่มี /dev/virtio-ports/org.qemu.guest_agent.0 ให้ poweroff จาก Guest → เปิด Agent ใน Options → Start ใหม่ให้ครบวงจร การติดตั้ง package อย่างเดียวไม่สร้างอุปกรณ์

หลังพร้อมใช้งาน ให้ lock รหัส ubuntu, ล้าง authorized_keys ชั่วคราว, apt-get clean, cloud-init clean --logs --machine-id และ poweroff ห้าม Start ก่อน Convert ตรวจ stopped แล้วลบ cipassword/sshkeys/cicustom เฉพาะรายการที่มีและไม่ได้ใช้ จาก Node ทำ qm cloudinit update และ qm template ตรวจ template: 1 / agent: 1 แล้วให้สิทธิ์ Template ใหม่และสลับใน Portal ตรวจ/เปิดระบบอีกครั้ง

เก็บ Template เก่าจน VM ใหม่ผ่าน SSH/IP/package acceptance แล้ว ระวัง Linked Clone dependency ก่อนลบของเก่า ไม่มีการลบเมื่อ Provisioning ล้มเหลว

## Endpoint และ CA

ใช้ URL ที่ hostname/IP ตรง Certificate SAN และ resolve ใน LAN ได้ Public CA มาจาก /etc/pve/pve-root-ca.pem บน Node ไม่ใช่ Private Key เช่น pve-ssl.key อัปโหลด CA ที่ Setup โดยไม่ปิด verification

Node คือโฮสต์สร้าง VM, Pool คือขอบเขตสิทธิ์, Storage คือที่เก็บ Disk, Bridge/allowlist คือเครือข่ายที่ Backend อนุญาต Template/Disk device/ขนาดขั้นต่ำต้องตรงต้นแบบจริง เช่น 3584M ปัดขั้นต่ำเป็น 4 GiB หรือคง resource policy ที่มากกว่าได้ เว้น Secret ว่างเพื่อเก็บค่าเดิมเมื่อแก้ Settings

## อายุ Session

**ตั้งค่า → Session**: ปรับได้ 5–1440 นาที มี presets 15/30/60/240/480 นาที ค่าที่บันทึกใน DB ใช้กับ Login ถัดไปทั้ง Admin/User เป็น absolute lifetime ไม่ใช่ idle timeout Session เดิมยังมี expiry เดิม การบันทึกไม่พัก Proxmox หรือแก้การเชื่อมต่อ

Logout และเปลี่ยนรหัส Portal เพิกถอน Session ตามเดิม Console จบไม่เกิน 15 นาทีและไม่เกินเวลาหมดอายุของ Portal token ที่เปิด Console ถ้ายังไม่ได้ตั้งค่าผ่านเว็บ จะใช้ TOKEN_MINUTES จาก ENV เป็นค่าเริ่มต้น

## งานประจำวันและหน้าเว็บ

- **เครื่องเสมือน**: แสดงสถานะ Power/IP มีปุ่มเปิด/ปิดหลัก ส่วน Restart, บังคับปิด, Console, Reset และลบอยู่ใน จัดการ
- **คำขอสร้าง VM**: กรอก hostname โดยไม่เติมเลขท้าย CPU/RAM/Disk และ Guest credentials; ประวัติเก่าซ่อนไว้จนเลือกแสดง
- **รออนุมัติ** (Admin): รวมบัญชีใหม่, สร้าง VM, ลบ VM และรีเซ็ตรหัส VM ไม่กระจายปุ่มอนุมัติหลายหน้า
- **ผู้ใช้**: เปลี่ยนโควตาผ่านฟอร์มแยกช่อง และออกโค้ดกู้คืน Portal โดยยืนยันรหัส Admin
- **กิจกรรม**: แสดงงานที่ยังไม่เสร็จ/ต้องตรวจสอบก่อน มีตัวเลือกดูงานเก่าและรายละเอียดทางเทคนิค
- **บัญชีของฉัน** ที่หัวเว็บ: เปลี่ยนรหัส Portal และ Logout
- **บันทึกการใช้งาน** (Admin): Audit รวมการอนุมัติและคำสั่งสำคัญ รายละเอียดเปิดดูเป็นรายการ

ลบ VM ต้อง stopped, Admin พิมพ์ชื่อยืนยัน และคืน Quota หลัง Task สำเร็จเท่านั้น รหัส Portal/Guest แยกกัน กู้คืน Portal ใช้โค้ดครั้งเดียว 15 นาที ไม่มีอีเมล Reset Guest ต้อง Agent + Unrestricted และ Admin approval รายละเอียด [Password Recovery](PASSWORD-RECOVERY.md)

งาน clone_accepted ที่ connection สะดุดใช้ปุ่ม ทำต่อจาก Clone เดิม หลังตรวจ UPID OK ไม่ส่ง Clone ซ้ำ ส่วนผลคำสั่งไม่แน่นอนต้องตรวจ Task/Audit ก่อนดำเนินการ ไม่สร้างคำขอซ้ำเพื่อแก้ปัญหา

อ้างอิง: [Proxmox Cloud-Init](https://github.com/proxmox/pve-docs/blob/master/qm-cloud-init.adoc), [Ubuntu OpenSSH](https://ubuntu.com/server/docs/how-to/security/openssh-server/)

## การใช้งานเพิ่มเติม: บัญชี, Monitoring และ Console

สมัครสมาชิกต้องมีชื่อ–นามสกุล (รองรับภาษาไทย), Username, รหัสผ่าน 8–128 ตัว พร้อม A–Z, a–z, 0–9 และอักขระพิเศษ และยืนยันรหัสตรงกัน Backend ตรวจซ้ำทั้งหมด ผู้ใช้เดิมยังใช้บัญชีเดิมได้ ชื่อ–นามสกุลเดิมที่ยังไม่มีข้อมูลจะเว้นว่าง

หน้าเครื่องเสมือนของ Admin แสดงสุขภาพ Node (CPU, RAM, พื้นที่ Storage ของ VM, Uptime) อัปเดตทุก20วินาที ตัวเลข Node รวมการใช้ทรัพยากรบนโฮสต์ทั้งหมด ส่วนตาราง VM แสดงเฉพาะเครื่องที่ Portal บันทึกไว้ พร้อม Power/IP/CPU/RAM ผู้ใช้เห็นเฉพาะเครื่องของตน ค่า RAM เป็นข้อมูลที่ Proxmox รายงาน ไม่ใช่การตรวจ process ภายใน Guest; พื้นที่ VM อ่านจาก Storage ใน Setup เช่น local-lvm แสดงหน่วย GB/TB แบบฐานสิบ ไม่ใช่ root filesystem

Node health ใช้ Sys.Audit ที่ `/nodes/Node3` (หรือ Node จริงใน Setup) ส่วน VM metrics ใช้ VM.Audit บน VM/Pool หากอ่านไม่ได้ให้ตรวจ ACL ทั้ง User/Token เมื่อเปิด Privilege Separation ไม่มีการเพิ่มสิทธิ์ Administrator ให้อัตโนมัติ

Console / Shell เปิดแท็บใหม่ หากเบราว์เซอร์บล็อก popup ให้เปิดอนุญาตสำหรับ Portal ระบบยัง relay ผ่าน Backend, ใช้ ticket ครั้งเดียว และไม่ส่ง ticket/password ใน URL แท็บ Console ใช้ Session ของบัญชีที่เปิดมัน ไม่ตามการเปลี่ยนบัญชีในหน้าหลัก; Logout/เปลี่ยนรหัส/ลบบัญชีเพิกถอนสิทธิ์ฝั่ง Server

Login คงอยู่เมื่อรีเฟรชแท็บเดิมด้วย sessionStorage ไม่เก็บรหัสผ่าน/Proxmox credentials และไม่ใช้ localStorage Backend ยังคงตรวจ JWT expiry, auth_version และ account status ทุก API Session ไม่ต่ออายุเพียงเพราะรีเฟรช; ปิดแท็บ/พฤติกรรม restore ของ browser เป็นไปตาม browser ไม่ใช่หลักฐานการ Logout ต้องใช้ปุ่มออกจากระบบเพื่อเพิกถอน Login

## ลบผู้ใช้พร้อม VM

1. เข้า ผู้ใช้ → ลบผู้ใช้ (เฉพาะบัญชีที่ระดับต่ำกว่าตนเอง; ห้ามลบตนเอง)
2. ตรวจชื่อบัญชีและรายการ VM ทั้งหมดใน popup ไม่ใช้รายการที่ถูกตัดเหลือ200รายการเพื่อยืนยันลบ
3. Shutdown VM ของบัญชีให้ stopped รอ queued/running jobs จบ และตรวจ needs_review ก่อน
4. พิมพ์ Username ให้ตรง ระบุเหตุผล และยืนยันด้วยรหัสผ่าน Admin ของผู้ทำรายการ
5. Backend ตรวจรายการ VM ซ้ำ, ownership, identity/Node/execution mode, power และงานค้างทุกเครื่องก่อนสร้างงานลบใน transaction เดียว หาก VM เปลี่ยนระหว่างเปิดหน้าต่างต้องเปิด preview ใหม่
6. เมื่อรับงาน บัญชีเป็น `deleting`, revoke Login และ recovery codes, ยกเลิก pending requests และล้างรหัส Guest ที่ค้าง Worker ลบ VM ผ่าน workflow ที่ Admin อนุมัติแล้วเท่านั้น
7. บัญชีเป็น `deleted` หลัง VM ลบสำเร็จทั้งหมด เก็บประวัติ 7 วันก่อนล้างเมื่อไม่มีงานอ้างอิง งานค้าง/needs_review ยังเก็บไว้ เมื่อลบสำเร็จ (`deleted`) Username เดิมสมัครใหม่ได้ทันที บัญชีใหม่มี ID ใหม่และไม่สืบทอด VM/ประวัติ/รหัสผ่าน/Session ของบัญชีเก่า บัญชีที่ยัง `deleting` ยังสงวนชื่อไว้ ตัวเลือกแสดงประวัติอยู่ด้านล่างของรายการ
8. งานล้มเหลว: บัญชียังระงับ/VM เป็น needs_review ไม่ลบ record ทิ้งหรือ force stop/retry DELETE แบบเดาผล ให้ตรวจ Task ก่อน ใช้ retry เดิมได้เฉพาะ precondition stopped ที่พิสูจน์ได้ ระบบไม่ retry ผล DELETE ไม่แน่นอน

ข้อความ validation แสดงชื่อช่องและเงื่อนไขที่ต้องแก้ แทน JSON/error code ดิบ ข้อผิดพลาดระบบมีเลขอ้างอิงให้แจ้งผู้ดูแล รายละเอียดเทคนิคของงานอยู่ในส่วนพับสำหรับ Admin ไม่แสดงรหัสผ่าน, token หรือ upstream response body

### การจำหน้าและฟอร์มยืนยัน

รีเฟรชจะจำเมนูและแท็บย่อยของ Setup ในแท็บเดิมด้วย sessionStorage (ไม่เก็บข้อมูลฟอร์มหรือรหัสผ่าน) Logout/Session ที่ใช้ไม่ได้จะล้างหน้าที่จำไว้ กดเมนูตั้งค่าใหม่จะเริ่ม Proxmox เสมอ ส่วน Session ยังเลือกได้ตามเดิม ช่วงโหลดแรกแสดง loading state จนข้อมูลบัญชีพร้อม ไม่แสดง Login หรือเมนูผิดบทบาทชั่วคราว และ preload ฟอนต์ภายในเพื่อลด layout shift

ลบผู้ใช้/ออกโค้ดกู้คืนใช้ช่องยืนยันรหัส Admin แยกจาก form submit ไม่ประกาศเป็น current-password ไม่ส่ง username ของผู้ถูกลบเป็น Login และล้างช่องก่อนเรียก API ส่วนรหัส VM/Token ตั้ง autocomplete off และ password-manager ignore hints หน้า Login/สมัคร/เปลี่ยนรหัส Portal จริงยังคงใช้ semantics ตามปกติ

เว็บไซต์ไม่สามารถรับประกันการปิด password-manager popup ได้ทุก browser/extension; autocomplete เป็น hint และ browser บางตัวละเลยได้ ดู [MDN](https://developer.mozilla.org/en-US/docs/Web/Security/Practical_implementation_guides/Turning_off_form_autocompletion) การทดสอบอัตโนมัติตรวจ DOM, request payload, validation และไม่มี native form submission ใน confirmation ไม่ได้ตรวจ browser-owned password manager UI ทุกตัว

## โควตาเริ่มต้น

ผู้ใช้ → ค่าเริ่มต้น → เลือกแท็บ ผู้ใช้ หรือ Admin → กำหนดจำนวน VM/vCPU/RAMรวม(MiB)/Diskรวม(GiB) → บันทึก ค่าเริ่มต้นแยกเป็นสองชุด:

- ของผู้ใช้: ใช้กับสมาชิกที่สมัครใหม่ Admin ทุกระดับตั้งได้
- ของ Admin: ใช้กับบัญชี Admin ใหม่ (รวม Admin คนแรกตอนติดตั้ง) ตั้งได้เฉพาะผู้ดูแลหลักขึ้นไป

เมื่อเปลี่ยนระดับบัญชี (ยกระดับเป็น Admin หรือลดเป็นผู้ใช้) บัญชีที่ยังไม่เคยปรับรายคนจะย้ายไปใช้ค่าเริ่มต้นของระดับใหม่ ยกเว้นเมื่อทรัพยากรที่จองอยู่เกินค่าใหม่ บัญชีที่ปรับรายคนแล้วคงค่าเดิม

ถ้าเลือก “ปรับบัญชีเดิมที่ยังใช้ค่าเริ่มต้นด้วย” ระบบปรับเฉพาะบัญชีระดับนั้นที่ยังไม่เคยกำหนดโควตาเอง ข้ามบัญชีที่ระดับเท่ากับหรือสูงกว่าผู้บันทึก บัญชีที่ถูกลบหรือกำลังลบ และบัญชีที่มีทรัพยากรจองเกินค่าใหม่ รายงานจำนวนที่ปรับและที่ข้ามหลังบันทึก

การกดแก้โควตารายคนจะทำให้บัญชีนั้นเป็น “กำหนดเอง” แม้บันทึกเท่าค่าเริ่มต้นก็ตาม จึงไม่ถูกทับจากการปรับค่าเริ่มต้นครั้งต่อไป Migration0010 ใช้ประวัติ account.quota.updated หรือค่าที่ต่างจากค่าเดิม3VM/8CPU/16384MiB/200GiB เพื่อป้องกันบัญชีที่เคยแก้ไว้ และไม่เปลี่ยนตัวเลขโควตาปัจจุบัน

ปุ่ม Setup แสดงเหตุผลเมื่อกดไม่ได้ และแสดงรายการที่กำลังดำเนินการ ปุ่มตรวจเชื่อมต่อใช้สีอ่อน เปิดระบบสีเขียว พักระบบสีแดงเมื่อกดได้; เมื่อพักอยู่ปุ่มพักเป็นสีเทาและระบุสถานะ การพักหยุดรับงานใหม่ แต่งานที่กำลังทำยังทำต่อจนจบ

## เหตุผลคำขอและยืนยันคำสั่ง VM

คำขอสร้างใหม่ต้องระบุเหตุผล3–1000ตัวอักษร ไม่เว้นว่างหรือใส่สัญลักษณ์อย่างเดียว เหตุผลแสดงใน รออนุมัติ และประวัติคำขอ แยกจากข้อความพิจารณาของAdminและคงอยู่หลังอนุมัติ คำขอเก่าก่อนmigration0011อาจยังไม่มีเหตุผล ระบบไม่แต่งข้อมูลย้อนหลัง

Shutdown/Restart ต้องยืนยันpopupที่แสดงชื่อVM กดยกเลิกจะไม่ส่งคำสั่ง ปุ่มอัปเดตIPอยู่ในคอลัมน์IP addressและอ่านPower/CPU/RAMด้วยจากBackend ปุ่ม?ของVMusernameอยู่ข้างlabelเหนือช่องกรอก

## ใช้งานบนมือถือ

เมนูหลักเปลี่ยนเป็นช่องเลือกด้านบน ตาราง VM และ Audit เปลี่ยนเป็นการ์ดเมื่อพื้นที่แคบ ฟอร์มเรียงคอลัมน์เดียวบนจอเล็ก ปุ่มอนุมัติ/บัญชีและ popup ตัดบรรทัดตามความกว้างจอ ชื่อเครื่องและข้อความยาวไม่ดันหน้าออกนอกจอ คำสั่งและตารางอ้างอิงในคู่มือเลื่อนภายในกรอบได้ ตัวเลือกแสดงประวัติอยู่ด้านล่างของแต่ละรายการ

## Popup จัดการผู้ใช้และสถานะคำขอ

แก้ไขโควตา โควตาเริ่มต้น และออกโค้ดกู้คืนเปิดเป็น popup เช่นเดียวกับการลบผู้ใช้ ปิดด้วยปุ่มหรือ Escape และคืนโฟกัสไปยังปุ่มเดิม ระหว่างส่งข้อมูลจะปิดไม่ได้เพื่อป้องกันสับสนกับผลคำสั่ง

ทุกฟอร์มตั้งรหัสบนเว็บมี checklist ตามนโยบายจริง: สมัครสมาชิก, สร้าง Admin ครั้งแรก, ตั้งรหัส VM ใหม่, เปลี่ยน/กู้คืนรหัส Portal และขอรีเซ็ตรหัส VM ส่วนช่อง Login, ยืนยันรหัส Admin และ Token Secret ใช้ยืนยันข้อมูลเดิม

ผู้ใช้ดูคำขอสร้าง/ลบ/รีเซ็ตรหัส VM ของตนได้ในเมนูคำขอสร้าง VM ผลพิจารณาแสดงทันทีโดยไม่ต้องเปิดประวัติ แยกรอ Admin, อนุมัติแล้วรอทำงาน, กำลังทำงาน, สำเร็จ, ยกเลิก, ปฏิเสธ และงานสะดุดที่ต้องให้ Admin ตรวจสอบ แสดงเหตุผลที่ปฏิเสธแยกจากเหตุผลที่ผู้ใช้ขอ ระบบบังคับ Admin ระบุเหตุผลเมื่อปฏิเสธผ่าน API ด้วย คำขอเก่าที่ไม่มีเหตุผลแสดงข้อความให้ติดต่อผู้ดูแล การอนุมัติไม่ถือว่างานสร้าง VM สำเร็จจน VM พร้อมใช้งาน

สถานะระบบอยู่ข้างเมนูผู้ใช้มุมขวาบน สีเขียวคือพร้อมรับคำขอ VM สีเหลืองคือยังไม่พร้อม กดเพื่อดูการตั้งค่า ผลตรวจการเชื่อมต่อ และการเปิดใช้งานล่าสุด Admin กดไปหน้า Setup ได้จาก popup นี้ ผู้ใช้ทั่วไปเห็นเพียงสถานะพร้อม/ยังไม่พร้อม เป็นป้ายที่กดไม่ได้ ไม่มี popup หรือรายละเอียดการตั้งค่า

Checklist ทุกฟอร์มตั้งรหัสใช้ 5 ข้อเหมือนหน้าสมัคร: ความยาว, A–Z, a–z, 0–9 และอักขระพิเศษ สมัครใช้ขั้นต่ำ8ตัว ส่วนสร้างAdmin/ตั้งรหัสVM/เปลี่ยนและกู้คืนรหัสใช้ขั้นต่ำ12ตัว ตรวจเงื่อนไขซ้ำที่Backendด้วย ข้อผิดพลาดระบบยังไม่พร้อมในบัญชีUserแสดงเพียง “ระบบยังไม่พร้อม” ไม่แนะนำให้UserไปSetup ส่วนAdminยังเห็นวิธีตรวจและเปิดระบบ

Popup เหตุผล/ยืนยันคำสั่งใช้ปุ่มธรรมดาแทน form submit ช่องเหตุผลเป็น textarea พร้อม autocomplete off และ password-manager ignore hints ส่วนยืนยัน Hostname ยังคงชื่อให้ตรงและกด Enter ได้ การขึ้นบรรทัดใหม่ในช่องเหตุผลไม่ส่งคำสั่ง การบันทึกรหัสของเบราว์เซอร์/ส่วนเสริมยังเป็นพฤติกรรมของแต่ละโปรแกรม ดู [ข้อจำกัด autocomplete](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/autocomplete)

## VM หายจาก Proxmox ภายนอก Portal

กดคำสั่งหรือปุ่มอัปเดต IP/ตรวจสถานะ ระบบจึงตรวจเครื่องกับ Proxmox ไม่มีการตรวจหายทุกนาที หากพบว่า VM ย้าย Node ชื่อเปลี่ยน ถูกล็อก สิทธิ์ไม่พอ หรือ Cluster ขัดข้อง จะไม่ปิดรายการหรือคืนโควตา หากยืนยันไม่พบ จะแสดง “ไม่พบ VM ใน Proxmox” พร้อมระงับคำสั่ง ให้ Admin กด **ยืนยันการลบจากภายนอก** และพิมพ์ชื่อเครื่อง ระบบตรวจซ้ำแล้วจึงปิดรายการ/คืนโควตา ผู้ใช้ทั่วไปทำขั้นตอนยืนยันนี้ไม่ได้

การยืนยัน VM หายโดยผลตรวจของ Portal ต้องมี Sys.Audit บน `/` สำหรับอ่านสถานะ Cluster ทั้ง Service User/Token ส่วนปุ่มตรวจสถานะใช้ตรวจซ้ำเมื่อ VM กลับมาได้ และจะคืนสถานะก่อนหายเมื่อข้อมูลเครื่องตรงเดิม ดูเงื่อนไขและข้อจำกัดใน [คู่มือ Operations](OPERATIONS.md#vm-ถูกลบหรือเปลี่ยนจาก-proxmox-ภายนอก-portal)

Admin ที่ตรวจใน Proxmox แล้วสามารถยืนยันการลบจากภายนอกพร้อมพิมพ์ชื่อ VM ได้ แม้ Portal ขาด Sys.Audit บน `/` โดยบันทึกแหล่งการยืนยันเป็น admin_proxmox_review ไม่คืนโควตาอัตโนมัติ และยังปฏิเสธเมื่อพบ VM, ย้าย Node, ติดล็อก, การเชื่อมต่อผิดพลาด หรือมีงานทำอยู่

### กำหนดสิทธิ์ใช้ทรัพยากรหลายบัญชี

ในหน้า **ผู้ใช้** กด **เลือกหลายคน** เพื่อเปิดช่องเลือก แล้วเลือกช่องหน้าชื่อบัญชี หรือ **เลือกทั้งหมด** แล้วกด **กำหนดสิทธิ์ใช้ทรัพยากรให้ผู้ใช้ที่เลือก** กรอกจำนวน VM, vCPU รวม, RAM รวม และ Disk รวม ค่าใหม่เป็นเพดานต่อคนและใช้เท่ากันกับทุกบัญชีที่เลือก ไม่ใช่ทรัพยากรกองกลาง หากบัญชีใดใช้ทรัพยากรเกินค่าใหม่หรืออยู่ระหว่างลบ ระบบจะไม่บันทึกทั้งชุด การกำหนดรายคนยังทำได้จากปุ่ม **แก้ไขสิทธิ์ใช้ทรัพยากร** และมีประวัติการแก้ไขแยกแต่ละบัญชี

### เลือกทรัพยากรจาก Proxmox

ในหน้า **ตั้งค่า → Proxmox** กรอก Endpoint, Token และ CA แล้วกด **โหลดรายการใหม่** ได้ทันทีโดยไม่ต้องบันทึกก่อน จากนั้นเลือก Node, Resource Pool, Storage ที่รองรับ VM image, Network Bridge และ Template จากรายการ เปลี่ยน Node หรือ Template แล้วระบบจะอ่านรายการที่เกี่ยวข้องใหม่ เลือก Boot disk และอ่านขนาด Disk จริงมาช่วยกำหนดขั้นต่ำ (ปัดขึ้นเป็น GiB) กำหนดขั้นต่ำสูงกว่าขนาดจริงได้ และเพิ่ม Bridge ที่เลือกเข้า allowlist ให้อัตโนมัติ

รายการจำกัดตามสิทธิ์ Token อ่านแต่ละส่วน ถ้าบางส่วนอ่านไม่ได้จะแจ้งแยกและเก็บค่าที่กรอกไว้ ช่องต่าง ๆ เลือกจากรายการแนะนำหรือพิมพ์เองได้โดยไม่ต้องสลับโหมด การดึงรายการเป็น GET ไป Proxmox ไม่บันทึกค่า ไม่พัก/เปิดระบบ และไม่ใช้ Sys.Audit ที่ `/` เพื่ออ่านสถานะ Cluster ส่วนการบันทึกและตรวจ Read-only ก่อนเปิดงานยังทำตามเดิม หากเปลี่ยน Endpoint หรือ Token ID ต้องกรอก Secret ของการเชื่อมต่อใหม่ ระบบไม่ส่ง Secret ที่เก็บไว้ไปยัง Endpoint อื่น

### เลือกจำนวนขาเครือข่ายของ VM

หน้า **ตั้งค่า → Proxmox** เลือก Node และ Template ก่อน จากนั้นเลือก Storage และ Pool ในช่อง **เครือข่ายของ VM** ติ๊ก Bridge ที่ต้องการเชื่อมต่อ จำนวนขาจะนับให้อัตโนมัติในช่องเดียวกัน หากต้องใช้ Bridge เดิมหลายใบ ให้เลือก **กำหนดแต่ละขาเอง** แล้วเพิ่ม/ลบแถว รองรับ 1–32 ขา รับ IP แบบ DHCP ทุกขา และเพิ่ม Bridge เข้า allowlist ให้อัตโนมัติ ไม่ต้องกรอกชื่อ Bridge ซ้ำ

ตรวจสรุปสำหรับ VM ใหม่ก่อนกดบันทึก ค่า Boot disk และขนาดขั้นต่ำอ่านจาก Template ให้แล้ว หากต้องแก้ให้เปิด **ตัวเลือกเพิ่มเติม** กด **บันทึกและตรวจสอบ** แล้วกด **เปิดใช้งานระบบ** เมื่อตรวจผ่าน นโยบายเครือข่ายใหม่ใช้กับ VM ที่สร้างใหม่ ไม่เปลี่ยน VM เดิม และแต่ละเครือข่ายต้องมี DHCP จึงจะได้ IP อัตโนมัติ Template ใช้ net0 ใบเดียวได้ Portal เพิ่มขาที่เลือกหลัง Clone ไม่ต้องเตรียมจำนวนขาใน Template ล่วงหน้า

### หน้าตั้งค่าแบบย่อ

เมื่อเปิดหน้าตั้งค่าที่เคยบันทึกแล้ว ระบบยุบข้อมูล Endpoint/Token/CA และโหลดรายการทรัพยากรให้อัตโนมัติ โดยไม่แก้ค่าที่บันทึกไว้ เลือกเครื่องแม่ข่าย ต้นแบบ ที่เก็บ Disk และกลุ่ม VM จากรายการ ช่องที่ยังว่างและมีตัวเลือกเดียวจะเติมให้ ส่วนเครือข่ายให้ติ๊ก Bridge ที่ต้องการ ใช้ DHCP ทุกขา

ปุ่ม **บันทึกและตรวจสอบ** บันทึกแล้วตรวจ Read-only ต่อทันที หากไม่มีการแก้ค่า ปุ่มจะเป็น **ตรวจการเชื่อมต่อ** และตรวจอย่างเดียว หากตรวจล้มเหลวจะแจ้งชัดว่าค่าบันทึกแล้ว แต่ยังเปิดใช้งานไม่ได้ กดตรวจซ้ำได้โดยไม่บันทึกใหม่ การเปิดใช้งานจริงยังต้องกด **เปิดใช้งานระบบ** และยืนยันเอง ไม่มีการเปิดระบบอัตโนมัติ

### ตำแหน่ง CA และการกรอก Node

CA มาตรฐานที่ Proxmox สร้างให้ อยู่ที่ `/etc/pve/pve-root-ca.pem` บน Node ใน Cluster เปิด Proxmox → Node → Shell แล้วอ่านด้วย `cat /etc/pve/pve-root-ca.pem` นำเนื้อหาไปวางในช่องใบรับรองเอง หรืออัปโหลดไฟล์ `.pem` นี้ หากใช้ใบรับรององค์กรให้ใช้ CA ของผู้ออกใบรับรองนั้น อ้างอิง [Proxmox Certificate Management](https://github.com/proxmox/pve-docs/blob/master/certificate-management.adoc)

ช่อง Node เลือกชื่อจากรายการหรือพิมพ์เองได้เสมอ แม้ Token อ่านรายชื่อไม่ได้ เมื่อแก้ชื่อแล้วออกจากช่อง ระบบจะโหลดทรัพยากรของ Node นั้นใหม่ สถานะ ปุ่มบันทึก/ตรวจสอบ และปุ่มเปิด/พักระบบอยู่แผงด้านขวาบนจอคอม และเรียงลงด้านล่างบนจอเล็ก

ตัวเลือกเพิ่มเติมเลือกจากรายการหรือพิมพ์เองได้เช่น Node: Boot disk มีคำแนะนำจาก Template, ขนาด Disk กำหนดตัวเลขเองได้ ส่วนรายชื่อ Bridge ที่อนุญาตสร้างจากเครือข่าย VM ที่เลือกโดยอัตโนมัติ ไม่ต้องกรอกซ้ำ ปุ่ม ? แสดงคำอธิบายเมื่อชี้ตรงตัวปุ่ม หรือกดปุ่มด้วยเมาส์/คีย์บอร์ด

ช่องที่อ่านรายการได้จะแสดง dropdown ครบทุกรายการ เช่น Template 9100 และ 9200 ไม่กรองตามค่าปัจจุบัน ใช้ได้กับ Node, Template, Storage, Pool, Boot disk, ขนาด Disk และ Bridge ในโหมดกำหนดแต่ละขาเอง เลือก **กรอกค่าเอง…** หากต้องการพิมพ์ และกดลูกศรกลับมาดูรายการได้ หากอ่านรายการไม่ได้ ช่องจะให้พิมพ์ได้โดยตรง

คำสั่งราย VM ทั้งหมดอยู่ใน dropdown **จัดการ** รวมอัปเดต IP/ตรวจสถานะ เปิด/ปิดเครื่อง Console รีเซ็ตรหัส ขอลบ และทำต่อจาก Clone เดิม ปุ่มยืนยันการลบจากภายนอกแสดงเฉพาะ Admin เมื่อ VM หาย หรือผลตรวจล่าสุดยืนยัน VMID ว่างแต่ขาดสิทธิ์อ่าน Cluster หากตรวจพบเครื่องหรือทำงานต่อสำเร็จ ปุ่มนี้จะไม่แสดง
